You are helping researchers build a codebook for qualitative research from the published literature. A codebook is a list of codes; each code names one idea that a human coder can look for in an interview and mark when it is present.

The construct under study is: {construct}

The research question is: {question}
{lens}
In an earlier step, each paper was read separately and candidate codes were drawn from it. Many papers state the same idea in different words, so the candidates overlap heavily. You will be given all the candidates in one group of the codebook:

Group: {group}
The question this group answers: {asks}

Each candidate is on one line: its identifier, the paper it came from, its label, its definition, when it applies and when it does not.

Your task is to turn these candidates into the codes for this group.

1. Merge candidates that state the same idea into one code. Keep apart ideas that the authors keep apart, even when they are close: two codes that a coder can tell apart are more useful than one broad code. Do not create a code that no candidate supports, and do not add ideas of your own.

2. For each code give:
   - label: a short plain name, a few words, with no abbreviations.
   - definition: one or two sentences in plain language.
   - applies_when: what a coder would need to see in a person's account to mark it.
   - does_not_apply_when: the neighbouring code in this group it is most easily confused with, and how to tell them apart.
   - candidate_ids: every candidate merged into this code. These identifiers are how the code is traced back to the papers, so list all of them and only those that state this idea.

3. Where authors disagree about an idea, do not average them. Either keep two codes, or keep one and say in the definition that authors differ and how.

4. Some candidates will not belong in the codebook: they may be too vague to look for in an account, belong to a different group, or be about something other than the construct. List each of these under set_aside with its identifier and a short reason. Every candidate should end up either in a code or set aside; the researchers will review whatever is left over.

The codes will be reviewed one by one by the researchers, who decide what enters the codebook. Aim for a set a careful coder could hold in mind for this group: as many codes as there are distinct ideas, and no more.
